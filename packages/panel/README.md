# ChorusPanel

Web management UI for SingChorus, migrated from Python/NiceGUI to Node.js/Vue 3.

## Tech Stack

- **Frontend**: Vue 3 + Vue Router 4 + Pinia + Naive UI + Axios
- **Backend**: Express 4 + bcryptjs + jsonwebtoken + cookie-parser
- **Build**: Vite + vue-tsc + TypeScript

## Quick Start

### 无需克隆仓库（npx）

npm 包内置预编译产物，直接运行即可，无需构建工具：

```bash
npx @chorus/panel start                # 默认 127.0.0.1:8088
npx @chorus/panel start -p 8088 --host 0.0.0.0
```

### 仓库内开发

```bash
# Install dependencies (from repo root)
pnpm install

# Development (both server + frontend with HMR)
pnpm --filter @chorus/panel dev

# Production build
pnpm --filter @chorus/panel build

# Start production server
pnpm --filter @chorus/panel start
```

### 开发模式：通过自定义域名访问（Vite host 白名单）

Vite dev server 出于防 DNS rebinding 攻击的考虑，默认拒绝非 localhost 的 `Host` 头。如果你通过反向代理/隧道用自定义域名（如 `oxd.imuuu.eu.org`）访问 `pnpm --filter @chorus/panel dev`，会遇到 `Blocked request. This host is not allowed` 报错。

解决方式：域名写入 `packages/panel/.env.local`（已被 gitignore，不入库），`vite.config.ts` 会自动读取：

```bash
# packages/panel/.env.local
VITE_ALLOWED_HOSTS=oxd.imuuu.eu.org
```

说明：

- 多个域名用逗号分隔：`VITE_ALLOWED_HOSTS=a.example.com,b.example.com`
- 放行某个域名的所有子域用前缀点：`VITE_ALLOWED_HOSTS=.imuuu.eu.org`
- 也可在启动时临时注入：`VITE_ALLOWED_HOSTS=oxd.imuuu.eu.org pnpm --filter @chorus/panel dev`
- 该变量不设置时白名单为空，保持 Vite 默认严格校验

注意：此限制仅存在于 Vite dev server。生产部署用 `npx @chorus/panel start`（Express 托管预编译 `dist-web`），任意域名均可访问，无需任何配置。

## Architecture

The panel server runs on port 8088 and serves:
- Vue SPA (static files from `dist-web/`)
- Auth API (`/api/auth/*`) — local JWT-based auth with bcrypt password hashing, login rate limiting, and token versioning (password changes invalidate existing sessions)
- Core API (`/api/core/*`) — calls the `@chorus/core` library directly in-process (no HTTP proxy; the cloud URL/token is configured in settings)
- Init API (`/api/init/*`) — first-run wizard (node identity + cloud connection)
- Settings API (`/api/settings`) — panel configuration (cloud URL/token, node identity)
- Info API (`/api/info`) — system information + background sync health

Auth uses an HttpOnly JWT cookie (`chorus_panel_token`) with 12h TTL. State-changing requests are additionally protected against CSRF via an Origin check.

First run requires setting an admin password. After that, login is required for all operations.

## Configuration

Config stored at `~/.singchorus/panel/config.json`:

```json
{
  "admin_password_hash": "<bcrypt hash>",
  "core_url": "http://127.0.0.1:8080",
  "core_token": "",
  "jwt_secret": "<auto-generated>",
  "token_version": 0,
  "node_name": "",
  "node_address": "",
  "initialized": false
}
```

Environment variables:
- `CHORUS_PANEL_PORT` — server port (default: 8088)
- `CHORUS_PANEL_HOST` — server host (default: 127.0.0.1)
- `CHORUS_PANEL_CORS_ORIGIN` — comma-separated CORS allow-list for cross-origin API access (required for cross-origin use in production)

## Pages

| Route | Description |
|-------|-------------|
| `/login` | Admin login / first-run password setup |
| `/dashboard` | Stats overview + recent configs |
| `/configs` | Config list with enable/disable/delete |
| `/configs/create` | 3-step config creation wizard |
| `/configs/:name` | Config detail with JSON editors + validation |
| `/deploy` | Deploy/restart/stop + log viewer |
| `/validate` | Multi-mode validation (Entry/Merged/Subscription/Generic) |
| `/templates` | Protocol template cards with schema details |
| `/subscriptions` | Enabled client configs + subscription validation |
| `/settings` | Node identity, cloud connection, system information, password change |

## CLI Integration

`chorusctl panel start` (Node CLI) detects Node.js availability, auto-builds if needed, and starts the panel server via subprocess.
