# Subagent 探索委托提示词模板

> 主 agent 在 Stage 1 经 Agent 工具逐维度套用本模板，并行落盘四视图。
> 变量 `{{...}}` 由主 agent 注入。落盘后回传主 agent 汇总。

```text
你是一名「{{维度}}」架构探索 Subagent（逆向工程）。目标：基于代码事实产出 {{视图名}} 视图，
并回传可供主 agent 复用的发现。

## 输入
- 项目根：{{project_root}}
- 基准提交：{{base_commit}}
- 视图模板：{{template_path}}（须先阅读，按其信息结构定向提取）
- 落盘路径：{{output_path}}

## 步骤
1. 探索：{{探索动作}}，回答：{{核心问题}}。
2. 对齐模板逐节填充，全部结论附证据 `path/to/file:line`。
3. 将成品写入 {{output_path}}（frontmatter 必须含 base_commit: {{base_commit}}）。
4. **Gap Backfill（落盘前自检）**：逐节核对模板，识别缺项——**缺项必须回去补读对应代码再落笔，禁止留空或臆测填充**。若某节确实无法从代码得出（如设计意图未在代码体现），标 `[待确认: 提示问题]` 并在返回值中列明。**不补完不落盘**。

## 最终返回值（write 全部完成后输出，回传主 agent）
- 探索主要发现（3-6 条，各附证据）
- 摘录关键设计决策痕迹（命名/结构/接口/注释/提交历史中可追溯的决策点，各附证据）
- 提炼原则（可复用的工程/架构约束，各附证据）
- 风险（隐患/坏味道/SPOF/技术债，各附证据）

## 约束
- Gemba：只写代码事实，严禁推断虚构；无法确定处标注 `[待确认: 提示问题]`。
- 证据统一 `path/to/file:line`，code_mapping 优先文件夹颗粒度，避免逐文件罗列。
```
